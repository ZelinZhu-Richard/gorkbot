# Competitor and Adjacent Product Research Queue

This is an investigation list, not a claim that every product is a direct competitor.

- persistent named agents
- user-scoped persistent cloud computer
- browser, filesystem, terminal, connectors, and GUI use
- background work

- skills and routines
- approvals and takeover

- team controls

Study product patterns from:

## Required comparison dimensions

For every product capture:

- target customer
- primary job to be done
- persistent identity
- persistent execution environment
- background work
- browser, terminal, and files
- API and connector support
- local-computer access
- model choice
- multi-agent behavior
- groups and handoffs
- memory
- skills and routines
- approvals
- observability
- mobile supervision
- security boundary
- pricing unit
- deployment model
- export and portability
- major limitations
- evidence quality

## Strategic questions

- Which products complete external work rather than generate drafts?
- Which ones provide verifiable completion?
- Where does model lock-in matter to customers?
- Is multi-agent collaboration valuable, or mostly a demo feature?
- Which workflows tolerate occasional failure?
- Which customers will pay before the platform is broad?
- What advantages can survive model-provider improvements?
- Where can a small team create a superior product through focus rather than infrastructure scale?

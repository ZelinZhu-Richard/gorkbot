## Platform-necessity screen

The platform question is not scored as a positive “fit” bonus. It is a qualitative constraint: **does the workflow need durable autonomous state and several tools, or can a product feature/schedule solve most of it?**

| Class | Meaning |
|---|---|
| Product feature | A bounded function inside an existing system; no durable autonomous runtime required. |
| Scheduled automation | Repeated trigger plus limited run history; durable agent identity/context is not necessary for most value. |
| Persistent single agent | One durable workspace/agent materially benefits from accumulated context. |
| Multi-tool persistent agent | Durable state plus multiple systems, approvals, recovery, and external-state checks materially matter. |
| Multi-agent team | Multiple independently acting roles are necessary rather than merely possible. |

| Hypothesis | Minimum sufficient class for most value | Analysis |
|---|---|---|
| H1 | Scheduled automation | Page monitors and scheduled assistants already solve detection/digest. A multi-tool persistent agent may help with a governed master-record update, but that residual value is untested. |
| H2 | Multi-tool persistent agent | Repository, test environment, CI, PR, and review state benefit from durable background execution; current coding-agent products already provide this runtime. |
| H3 | Product feature or scheduled automation | Governed notebooks/analytics products can run reproducible checks and reports without a general persistent platform. |
| H4 | Product feature | Evidence-linked synthesis is already a research-repository function; persistence may help memory but is not necessary to the bounded job. |
| H5 | Scheduled automation | Corpus alerts and refresh reports can be scheduled product workflows; a persistent agent is optional. |
| H6 | Multi-tool persistent agent | Code, browser QA, preview host, and approval cross systems, but existing coding-agent plus preview products already cover the runtime. |
| H7 | Multi-tool persistent agent | Browser state, spreadsheet/record reconciliation, approvals, and recovery create the clearest platform-runtime need, alongside the highest safety risk. |
| H8 | Multi-tool persistent agent | Clean reproduction, repository/CI readback, and evidence packaging cross tools; it may still be absorbed as a coding/review product feature. |

No current hypothesis requires a multi-agent team. Independent author/verifier separation may improve H8 assurance, but customer need and the incremental benefit over deterministic CI/review remain untested.
